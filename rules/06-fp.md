Always use fpdart.

Don't throw exceptions if we don't need to. Try-catch's should only be 1) at the boundary of packages; or 2) using TaskEither; or 3) when there remains no other choise. The only, um, deviation to this are very low-level services like http, sembast, database, etc. that use exceptions as a matter of course. And then use `TaskEither.tryCatch`, wrap the exception as a Failure, and flow it out.

If you're reaching to return `Future<Either<Failure, SomeClass>>`, then use `TaskEither<Failure,SomeClass>` instead.

Never return `void` when Unit is appropriate in a return.

## ReaderTaskEither

ReaderTaskEither and the Reader pattern is okay if it's already spec'd, especially for usecases. But be explicit and add comments that explain chaining or mapping.

However, I don't care for the typedef-backed style since we have to alias them anyway in the import statements. So again, unless we already have them, don't create new ones unless asked.
